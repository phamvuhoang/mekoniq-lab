## Fault policy and deliberate limitations

Server-owned `faults` entries are allowlisted `{id, kind, atSimMs, durationMs}`; IDs are unique, there are at most 100 entries, start times are bounded to one hour and windows to 60 seconds. Intent is atomically written and fsynced before the injection. Supported hooks are missing cup (latched physical absence), grip failure (controller simulation scene), AMR disconnect/delay (native adapter boundary), blocker (pinned Gazebo model), and tunnel loss (close the actual configured connection). AMR delay is capped at 1 second per native request. These are explicitly injected simulation failures, not claims of observed hardware failure.

Controller restart can be exercised by the protocol-double restart hook; real provider configuration rejects it with `NATIVE_CONTROLLER_RESTART_REQUIRES_EXTERNAL_OPERATOR`. This implementation does not restart an externally managed controller process. A real externally induced restart is detected as owner/epoch/reconcile loss. Imported project `faultSchedule` and legacy campaign schedules are rejected explicitly; they are never ignored or silently translated. Native scheduled fault UI remains unavailable until that vocabulary is mapped to this server-owned policy. Live fault repetitions remain not_run.

Native readiness performs bounded inventory and bridge probes without ownership or motion, then the factory revalidates the compiled bundle hashes, canonical project, controller model, provider capabilities and negotiated grip/barrier on opening. A successful readiness inventory is preflight evidence, not a native execution claim. Reopened runs intentionally offer journal inspection and an audit-only reconciliation action; live provider outcome queries/rebinding are not implemented in that read-only path.
